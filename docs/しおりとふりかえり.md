# しおりとふりかえり

本を開くと、取り込んだ本文を縦書きでページ表示する。全文を画面の大きさ・文字サイズ・行間に合わせて実測し、ページを区切る。文字数による途中の区切りは設けない。計測用の本文は文字ノードで扱い、表示中のページだけを操作用の文字に分ける。操作画面はReact Native、縦書きの紙面はDOMコンポーネントで、Web・iOSが同じ実装を利用する。

## 操作

1. 右上のしおりマークを本文へドラッグし、最後に読んだ文字で離して挟む。マークのタップは一覧、長押し後に離すと従来の位置選択になる。一覧の「しおりを挟む」からも文字を選んで確定できる。
2. 一覧の「移動」から、別の文字やページを選んで挟み直す。確定まで元の印を薄く残し、キャンセルできる。移動直後は「元に戻す」が使える。
3. 「外す」で解除。「ここから読む」で元の文字があるページへ戻る。ページ末尾のしおりでも、勝手に次のページへ進めない。
4. 「ふりかえり」は「前回から」「この章」「最初から」を選ぶ。「前回」は本文上でひとつ手前のしおり。「この章」は「第一章」「一」など独立行の見出しを基準とし、見出しのない作品は冒頭からとなる。

紙面のしおりは直接ドラッグして移動できる。元の印を薄く残し、動かす印は通常の色で指に追従する。紙面の左右端で約0.65秒待つとページをめくり、押したままなら繰り返す。紙面上で離すと保存し、紙面外で離す・操作が中断される場合は元の位置を保つ。移動開始や完了のお知らせで紙面の大きさを変えない。

右上からの新規ドラッグでも、元のヘッダーマークを薄く残し、通常色のマークが指に追従する。ドラッグ中は位置選択バーを出さず、紙面とヘッダーの寸法を保つ。画面座標は紙面に対する相対座標にしてDOMへ渡すため、iOSのWebView内でも同じ文字位置の判定を使う。左右端で待つ操作は既存のページ送りを使い、本文外で離した場合や操作中断時は追加しない。文字位置が確定した場合だけ、従来の保存処理でしおりを追加する。

小説の本文は、ページごとの余白と境界線を残した横スクロールで読む。右へ指を動かすと先へ進み、途中でも止められる。ページ単位のスナップや紙面タップによる送りは行わない。Webではマウスドラッグ・ホイール・トラックパッドでも操作できる。手動操作時には読みガイドを一時停止する。画面内で表示面積の多いページにページ番号と読書位置が追従し、ページバー・しおりからの移動や読みガイドの自動送りでは対象ページの先頭に合わせる。教材の表示方式は変更しない。

下部に「現在ページ / 総ページ数」を表示する。バーのタップ・ドラッグでページを選び、指を離すと移動する。右端が最初、左端が最後。ページ数は画面や設定ごとに変わるため、端末間で同じ番号になるとは限らない。ページ移動だけではしおり・ふりかえりの既読境界を進めない。

## 表示設定

「Aa 表示設定」から文字サイズ（17・18・22・24・28・32）、書体（明朝・ゴシック・丸ゴシック）、行間（5段階）、紙の色（明るい紙・生成り・グレー・暗い紙）を選んで適用する。標準は17px・行送り34px。保存済みの設定は引き継ぎ、「標準に戻す」で標準値へ変更できる。書体は端末にあるフォントを利用し、対応書体がない場合は代替書体になる。設定はAsyncStorageへ全作品共通で保存し、次回も利用する。キャンセル時には反映しない。設定変更や画面幅の変更では、直前に見えていた文字を含むページへ移動する。しおりの文字位置やふりかえりの対象範囲は変更しない。

本文の境界はUTF-16の文字位置で保存し、サロゲートペアの途中を拒否する。ページ表示だけではしおり・既読範囲は増えない。ふりかえりはしおり直前で打ち切り、同じ段落の先の文章も送らない。最大20,000文字。長い場合は別の範囲を選ぶか、中間にしおりを置く。範囲・分量カードや本文抜粋はふりかえり画面に表示しない。

## 保存

本棚・本文・しおり・閲覧位置・完成した要約はAsyncStorageに保存する。端末やブラウザーをまたぐ同期はない。保存失敗時は直前の記録を保ち、読み込みに失敗した既存記録を空データで上書きしない。同じ作品の本文が変更された場合、文字位置を誤用せず案内して停止する。

しおりは1冊200個まで。要約は範囲の本文も照合して再利用し、しおりを移動した先へ別の範囲のまとめを流用しない。保存済み要約の閲覧やしおり操作には通信しない。

## 起動とサーバー設定

```powershell
npm ci
npx expo start
```

しおり・読書は要約の設定がなくても利用できる。要約を使うときは、プロジェクト直下のローカル専用 `.env.local` に `OPENAI_API_KEY` を設定し、開発サーバーを再起動する。実際の値はGit・チャットへ貼らず、`EXPO_PUBLIC_` を付けない。

`src/app/api/summary+api.ts` がサーバー側で生成する。選択された本文だけを送信し、作品名・残りの本文は送らない。番号なし・段落間に空行の要約を指示する。これは生成内容の意味的な正確性を保証するものではない。

新規の要約はResponses APIの `gpt-5.4-mini` を使う。`reasoning.effort:none`、`store:false`、出力上限1,200トークンとし、追加の推論処理は使わない。モデル変更後も保存済みの要約を再利用し、自動で作り直さない。BGM選定には軽量な `gpt-5.6-luna`・`reasoning.effort:none` を使う。

新規生成はサーバー起動中20回・同時1回まで。同じ本文の同時要求は共有し、自動再試行しない。APIキーや外部サービスのエラー本文をクライアントへ返さない。

Expo Goでは開発サーバーへ接続する。TestFlightの要約機能は、HTTPSサーバーへAPIを公開し、expo-routerのoriginを設定してから使用する。公開APIの認証・利用制限をアカウント単位で管理する仕組みは別途必要。静的ファイルだけの配信には対応しない。

## 確認

`npm run typecheck` と `npm test`。テストの要約プロバイダーは偽物を使い、課金通信をしない。WebとiOSのバンドルは `npx expo export --platform web` と `npx expo export --platform ios` で確認できる。iOSの書き出しはJavaScriptの検証であり、EASビルド・TestFlight提出ではない。


## 読みガイドと操作の調整

書体は明朝・ゴシック・丸ゴシック・教科書体・クラシック明朝・読みやすいゴシック・システム標準の7種類。端末に書体がなければ近い書体にフォールバックする。
読みガイドは現在位置付近を太字にして、前後へなだらかに薄く・浮き上がる表示とする。速度は120〜3000字/分のスライダーと数字入力、初期値1200。ユーザー別に端末へ保存する。
しおりは掴み範囲を広げ、4px移動でドラッグを開始。詳細・ふりかえりは下ではなく右側のパネルに表示する。
ページ計測前は操作用の文字部品を全文生成せず、計測後の表示ページだけ生成する。ページ数・しおりのUTF-16境界・要約範囲は従来通り。
青空文庫の本文は同時要求を共有し、最大8冊のメモリキャッシュとサーバーの.local/aozora/book-ID.jsonを再利用する。初回の公式サイトへの通信は必要。
