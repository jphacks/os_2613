# 感想・レビュー・タイムライン

- 本棚の「紹介・レビュー」または読書画面の☆から本の紹介画面を開く。
- タイムラインの「感想を書く」から本・星1〜5・感想を入力する。
- 投稿にはWeb版のBluesky OAuth接続が必要。既存セッションには投稿権限がないので、最初だけ「投稿を許可する」で追加認可する。認証はBlueskyの別ウィンドウで行い、ドパBOOKsの投稿画面は移動させない。下書きは端末内に保存する。ポップアップが拒否された場合は許可を案内する。
- 「Blueskyにも投稿」は初期OFF。ONの時だけ標準の `app.bsky.feed.post` に題名・星・感想の抜粋を投稿する。ネタバレの本文は載せない。
- 本文全体や非公開の読書記録は送信しない。感想・星・表示名は公開レコードとなる。

投稿成功後はタイムラインへ戻り、短い完了通知を表示する。途中失敗は成功として扱わず、作成画面に再試行を表示する。

## 保存と集計

`app.dopabooks.review` に本ID・星・感想・表示名・ネタバレ有無・日時を保存する。レコードキーは本ID。アカウントDIDと本IDの組で1件とし、編集は上書き、平均と星別件数も1人1件。青空文庫は作品ID、教材は元の教材IDを使い、教材の章・難易度別に分散させない。

共有API `/api/reviews` は投稿本文や投稿者を信頼せず、渡されたAT URIのレコードをPLCで解決したPDSから再取得して検証する。表示する題名・著者は公式カタログの情報を使う。公開PDSへのリクエストにOAuthトークンは送らない。現在の検証対象はBluesky運営のPDS（bsky.social / *.host.bsky.network）。他社のPDSを使うアカウントにはエラーを表示する。

共有インデックスは `.local/reviews/` のファイルに原子的に保存する。サーバーを再起動しても残るが、同じ保存先を共有しない別サーバーやサーバーレス環境にはそのままでは対応しない。デモ用は1台のAPIサーバーへ接続する。本番ではこのインデックスを永続DBへ移す。最大1万件、一覧は30件ずつ。平均はページ内だけでなく、その本の全登録レビューから計算する。

API登録済みのレビューを表示する方式で、ATネットワーク全体の常時収集は行わない。アプリ外で直接レコードを編集・削除した場合、次の同期まで表示に残る。アプリからの編集・削除は同期する。Blueskyへ共有した投稿は独立しているため、レビューの削除で消さない。

## 障害・再試行

AT Protocolへの保存、共有インデックスへの反映、Bluesky投稿は別処理。途中失敗は「AT Protocolには保存済み」と区別し、同じ内容で再試行できる。Blueskyのレコードキーは仕様どおりTID形式にする。本文等のハッシュに対応するTIDと投稿日時を送信前に端末へ保存し、同じ内容の再送や画面再読み込みで二重投稿にしない。実アカウントへのテスト投稿は自動実行しない。

## OAuth / Lexicon

最小ログインは `atproto` のまま。メタデータには追加認可可能な `repo:app.dopabooks.review` と `repo:app.bsky.feed.post?action=create` を宣言する。公開Webのclient_idメタデータも同じスコープで配信する必要がある。

`lexicons/app.dopabooks.review.json` はデモ用の定義。現段階はPDSへ `validate:false` で保存してアプリ側で検証する。正式公開では所有ドメインに対応するNSIDを確定し、Lexiconを公開・解決できるようにして移行する。今の名前空間の所有や公開は完了していない。公式資料: https://atproto.com/ja/guides/permission-sets / https://docs.bsky.app/docs/tutorials/creating-a-post

iPhone開発ビルドのOAuthは元から未接続のため、閲覧はできても投稿はWeb版が必要。ネイティブ認証やウィジェットは今回変更しない。
