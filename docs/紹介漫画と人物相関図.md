# 紹介漫画と人物相関図

青空文庫から追加した小説で利用する。PDF教材は別の表示方式のため対象外。WebとiOSは同じReact Nativeの画面・検証モデルを使う。

## 紹介4コマ

小説を開くたびに紹介漫画の画面から始まる。「紹介漫画を作る」1回で脚本を作り、そのまま4コマの画像を生成する。脚本の承認や範囲選択の工程は見せない。上部の「原文を読む」で、漫画をスクロールせず、または作成せずに読める。読書履歴・しおりがある本も漫画を先に表示し、保存済みの漫画を再利用する。読書画面の「紹介4コマ」からも見返せる。

構成は「主人公・舞台 → きっかけ → 中心となる問題 → 未解決で続きが気になる場面」。紹介範囲は原文の先頭約35%・最大6,000文字、理解用は約60%・最大20,000文字。紹介範囲より後の出来事・解決・結末を紹介文にも絵にも含めないよう指示する。『走れメロス』は、先頭12,000文字以内にある「メロスは、すぐに出発した。」までを紹介範囲とし、中心となる約束まで届かせる。サロゲートペアの途中では切らない。

紹介範囲から180文字以内の連続引用候補を用意し、AIは各コマに対応する候補IDを選ぶ。引用文をAIに書き写させず、選ばれたIDから原文と文字位置を復元する。未知のIDや範囲外の位置は拒否し、原文との完全一致をサーバーと画面の両方で照合する。各コマの途中へ移動するボタンは置かず、画面の上部と完成した4コマのあとに「原文を読む」を置き、どちらも本の冒頭へ進む。上部のボタンは未作成・作成中・失敗時も表示する。紹介漫画を見ただけでは、しおりや既読の境界を進めない。「原文を読む」で本の冒頭へ進む。既存のしおりは保持し、読書画面のしおり一覧から続きへ戻れる。

新しい既定表示は吹き出し付きの漫画版（manga-v2）。脚本で人物・美術設定と4場面を確定し、各コマにセリフ・本文に明記された心の声・説明枠を1〜3個用意する。セリフと心の声は原文候補内の連続表現32文字以内、説明は候補に基づく48文字以内とする。吹き出しごとに資料IDから根拠を復元し、セリフの完全一致・文字数・配置の重複も検証する。原文にない会話や推測の心の声は作らせず、短い台詞がない場合は説明枠を使う。これは説明の解釈や絵の正確性を完全に保証するものではない。

絵は文字や吹き出しを含めず、人物の表情・動作と文字のための余白を描く。生成画像の上へReact Nativeで白い吹き出し、心の声、説明枠と確定済みの日本語を重ねる。画像モデルに日本語を書かせないため、画像内文字の文字化けや誤字を避けられる。コマ外の紹介文は新漫画版では表示せず、captionは画像の代替説明に使う。吹き出しの文字は縦書き、説明枠は横書き。狭い画面は1列、幅620px以上は右→左・上→下の2列で読む。絵単体のPNGには文字が入らず、アプリが絵と文字を一緒に表示する。

提供された参考漫画8枚を `assets/comic-references/` に元のまま保存する。実際の画像要求には幅768pxの絵柄見本を1枚だけ送り、線画・スクリーントーン・表情の方向性を参考にする。見本内の人物・服装・時代・建物・セリフ・物語は小説へ持ち込まないよう指示する。2〜4コマ目は小説の1コマ目も人物の連続性の参考にする。全景・対話・アップ・動作に画角の変化をつけ、写実的な筋肉や細密な劇画表現を避ける。見本の利用は生成の時間・料金・再現性を保証せず、画像入力料金が追加される。サーバー配信時にも参考画像のディレクトリを配置する。各コマと吹き出しの原文引用は、照合用データとして保持する。

## しおりまでの人物相関図

読書画面の「人物相関図」から開く。最後に操作したしおりを既定にし、別のしおりも選べる。作成ボタンを押すまで生成しない。しおりがなければ作成しない。

本文の先頭から、対象しおりのUTF-16文字位置の直前だけを切り出す。同じ段落の後半も含めず、作品名・漫画の理解用資料・残りの本文は送らない。10万文字を超える場合は黙って切り捨てず、手前のしおりを選ぶ案内を出す。

最大8人・関係12件。まず本文を最大1,200文字・300文字重複の資料へ区切って人物を抽出し、名前と資料IDを照合する。次に確認済み人物の組ごとに、両者の名前を含む最大1,200文字の資料を最大2つ選び、関係を別の要求で抽出する。人物の出現位置は1人80箇所まで本文全体から抽出し、関係語を含む箇所を優先する。関係の人物IDは確認済みIDの列挙に限定し、資料に指定した組と異なる関係は採用しない。

AIは引用文を書き写さず根拠の資料IDを選ぶ。サーバーは資料IDから原文を復元し、人物の引用は名前を含む120文字以内へ絞る。人物名は資料中に実在する呼び名のみ。関係名も原文の語句をそのまま用い、関係の連続引用には両人物の名前が必要。関係引用は1,200字まで。引用の存在と文字位置をサーバー・画面で再検証し、確認できない項目を除く。資料IDや人物名の不一致が一部にあっても、照合できた人物・関係は表示する。人物候補の根拠が全件不一致なら図を出さない。失敗時は照合段階と候補数・資料ID不一致数・人物名不一致数だけをサーバーへ記録し、本文・人物名・秘密はログに出さない。関係抽出後も人物数・関係候補数・確認できた関係数だけを記録する。作品知識・正体・将来の出来事を補わないよう指示し、検索ツールは使用しない。これは解釈の意味的な正確性や、同一人物の判定を完全に保証するものではない。関係がないときは推測で線を足さず、「関係をもう一度調べる」を押した場合だけ再生成する。

人物は色分けした共通の人物アイコンと名前で表示する。人物を一枚の図に一度ずつ配置し、関係名・矢印で結ぶ。関係名は横・斜めの矢印では線に沿った横書きとし、文字が逆さまにならない向きにする。縦から15度以内の矢印では文字を回転させず、上から下への縦書きに切り替える。縦書きもReact NativeのTextで表示し、長い関係文は線の長さに合わせて省略する。同じ2人の複数の関係は矢印を平行にずらし、人物や他の文字との重なりが少ない位置を選ぶ。長い関係文は図上で省略し、根拠欄には全文を残す。人物を選ぶとその人の関係を強調する。スマホでは図を横にスクロールできる。アイコンは外見・性別の推測を含まない。根拠は「原文の根拠を見る」で開き、人物・関係の引用から原文へ戻れる。対象のしおり・本文が変わると古い図を即座に消し、進行中の取得も中断する。

## 保存と再開

漫画版はサーバーの `comic-manga-v2`、端末の `dopabooks:comic:manga:v2` として旧版から分ける。本を開くと新しい漫画版の保存を確認するが、自動では生成しない。「以前の漫画を見る」から従来の画像＋紹介文形式や比較版へ戻れる。旧版の脚本・画像・生成回数は削除もリセットもしない。漫画版の初回は脚本と画像4枚の新規生成が必要。

完成済みの漫画には「比較用の別版を見る」を表示する。別版の画面で作成ボタンを押すと、新しい脚本と画像4枚を生成する。元の漫画は残し、「元の漫画を見る」で切り替えられる。切り替えや登録だけでは生成しない。画像のモデル・medium品質は共通で、今回は脚本の違いを比較する。別版は本文・作品ごとに1つだけで、サーバーと端末の保存キーを元の漫画と分ける。別版を再び開いたときは保存結果を使い、任意の版名で無制限に新規作成はできない。生成回数の上限は各版に適用する。

漫画の脚本・画像・生成回数はサーバーの `.local/book-comics/`、相関図は `.local/character-graphs/` に保存する。内容と形式バージョンのSHA-256で識別し、再起動後も同じ資料の保存を再利用する。漫画はコマごとに保存し、中断後は脚本・完成画像を作り直さず残りから再開する。保存操作は同じ識別子ごとに直列化し、JSONは一時ファイルから置き換える。壊れた既存記録は上書きしない。

端末側にも漫画の状態と相関図をAsyncStorageへ保存する。相関図は保存時の本文全体との一致を確認してから再利用する。資料ID方式の相関図は形式v2として旧形式と区別し、新しい形式の初回作成には利用者の操作が必要。漫画画像はexpo-imageのディスクキャッシュも使う。サーバーの保存は端末間同期ではなく、同じサーバーを利用する場合だけ共有する。`.local/` はGit対象外。

漫画は資料ごとに脚本最大3回・画像計8回。再起動後も回数を保持する。相関図の新規生成はサーバー起動中20回まで。1回の相関図作成で人物・関係のテキストAPI要求が最大2回発生する。連打は同じ処理にまとめ、異なる漫画の生成は同時1件。失敗時の自動再生成は行わない。状態照会・保存済み表示は生成を伴わない。

画像の上限に達して未完成の場合は「残りNコマを作る」を表示する。このボタンを押した場合だけ、未完成枚数分の試行を追加する。過去の回数はリセットせず、完成済みの脚本・画像を再生成しない。APIモジュールの再読み込み時も、同じNodeプロセス内の実行ジョブ・保存キューを共有し、進行中の処理を二重に開始しない。

作成失敗時は根拠不一致・接続・上限・時間切れ・保存失敗を区別して案内する。脚本の作成前に失敗した場合は、保存画像があるかのような案内を出さない。

## 接続

既存の `OPENAI_API_KEY` をサーバー側だけで使う。秘密を `EXPO_PUBLIC_` やソースへ書かない。漫画脚本・人物相関図のテキストはResponses APIのgpt-5.4-mini・reasoning.effort:none・Structured Outputs・store:falseを利用する。出力上限は吹き出し付き漫画脚本で10,000、それ以外で6,000トークン。画像は費用の急増を避けgpt-image-1.5・mediumを継続する。漫画版は縦長1024×1536、旧版は横長1536×1024。漫画版は1コマ目から見本付きのimages/editsを使う。モデル変更だけでは保存済みの脚本・漫画・相関図を作り直さない。新規生成または明示した相関図の調べ直しから新モデルを使う。参考：[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[構造化出力](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[画像生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[参考画像による編集](https://developers.openai.com/api/reference/resources/images/methods/edit)。

開発時のExpo Goは開発サーバーのhostUriへ接続する。配信版iOSは `extra.apiOrigin` またはexpo-routerプラグインの `origin` に公開HTTPSサーバーのURLを設定する。URLは秘密ではなく、APIキーはサーバーから外へ出さない。TestFlightへの更新配信と接続先の設定は配信担当者が行う。

画像生成は時間がかかるため、APIは開始を受け付けて状態照会で進捗を返す。常駐Nodeサーバーと書き込み可能な永続ディスクが必要。応答後に処理が停止するサーバーレス環境や複数サーバーでのジョブ共有には未対応。公開運用の利用者認証・利用者ごとの金額上限は別途必要。

## 確認

吹き出しのセリフが指定資料と一致しない場合は、紹介範囲全体で完全一致する本文位置を探す。それでも一致しないセリフ・心の声は採用せず、他の確認済み吹き出しを残す。全て除外されたコマは、その場面の有効な資料から短い本文抜粋を説明枠として配置する。不正な資料IDは引き続き失敗とする。旧条件の根拠不一致で脚本3回の上限に達した漫画版だけは、利用者が開始ボタンを押した際に一度限り追加の脚本試行を許す。実行済み回数は保持し、自動再試行しない。

`npm run typecheck`、`npm test`、Web/iOS両方へのExpo exportで確認する。テストでは偽の生成プロバイダーを注入し、実APIや有料の画像生成は実行しない。実際の脚本・画像の品質とiPhone実機の操作は利用者による確認が必要。

吹き出し版のブラウザー確認では、仮画像で縦書きのセリフ・心の声・説明枠、右上から読む2列配置、旧版から保存済み漫画版への切り替え、原文の1ページ目への移動を確認した。自動テスト104件と型チェックは通過。Web/iOSのexportも通過しているが、これはiPhone実機での表示や実際の画像生成品質を確認したものではない。実生成を試す際はサーバーを再起動し、本を開いて新しい漫画版の「紹介漫画を作る」を押す。旧版の完成済み画像を消す必要はない。

## 修正版漫画（revision 3）

新しい標準版は登録時にrevision:3を付け、端末のキャッシュをdopabooks:comic:manga:v3に分ける。従来の吹き出し版は「修正前の吹き出し版を見る」で残す。自動では作り直さない。脚本はgpt-5.4-miniを維持し、修正版の画像のみgpt-image-1-mini・medium・1024×1536へ変更。Miniではinput_fidelityを送らず、参考画像と最初のコマの入力は継続する。以前の版や生成途中の版は元のモデル設定を使う。修正版脚本にはgenerationとしてrevision・textModel・imageModelを保存し、画面にも表示する。

修正版のspeech/thoughtは、原文の「」の中にあり、発言または文の先頭から始まり、句点・疑問符・感嘆符で終わる連続引用のみを残す。地の文や読点で途切れる文章はセリフにしない。必ず各コマに完結した説明枠を要求し、全会話の照合失敗時も本文を文字数だけで切らない。短い完結文がなければ画像作成前に止める。かぎ括弧と文末の検査は話者や発言の意味を完全に保証するものではない。

脚本指示では、表示されないcaptionだけに重要事項を置かず、説明枠で目的・期限・代償を伝える。走れメロスの紹介範囲に三日と人質が実在する場合は、3・4コマの表示文に三日・人質・友・帰還の語があることも検査する。これは意味の正確性を自動で保証するものではない。人物ごとに年齢・輪郭・髪・ひげ・衣装・持ち物を変える演出設定を作り、各場面に人物と左右位置を明記する。吹き出し上部には話者名を小さく表示する。実際の外見の一貫性は生成結果で確認する。

修正版の検証では自動テスト108件、型チェック、Web/iOSのExpo exportが通過。仮プロバイダーを使ったブラウザーで話者名・使用モデル名・旧吹き出し版への切り替えを確認した。有料生成、Miniの描画品質、iPhone実機表示は未確認。

## 漫画脚本のモデル強化

漫画脚本（manga_introduction）はGPT-5.4・推論low・出力上限16,000トークン・要求時間上限180秒へ変更。画像はMiniのmediumを維持する。人物相関図など他の文章要求は従来設定のまま。保存済み脚本のモデル履歴は変更せず、GPT-5.4-miniとGPT-5.4の両方の記録を読める。

revision 3では説明枠をJSON Schemaの必須narration項目として会話配列から分離し、保存前にbottomの吹き出しへ組み込む。重要事項は全4コマの表示文を検査し、三日/3日、人質/身代わりの表記を受け付ける。API未完了・説明枠不足・物語の要点不足は異なる失敗コードで案内する。地の文のセリフ化や文章の途中切断を防ぐ検査は維持する。仮APIの関連テスト26件と型チェックで確認し、有料APIでは未検証。

脚本の試行上限に達した場合は「脚本を追加で1回試す」を表示する。脚本と、その完成後に進む画像生成の追加料金を案内する。利用者が押したときだけresumeScript:trueで上限を実行済み回数+1へ増やし、過去の回数はリセットしない。登録・状態照会・通常の開始では増やさず、保存済み画像は回収して再利用する。有料APIを呼ばない関連テスト26件と型チェックが通過。

## 脚本生成の待ち時間と失敗案の保持

漫画脚本のGPT-5.4は推論none・出力上限12,000へ変更し、要求には原文資料sourcesだけを入れてopening/contextの重複を省く。cast/title/caption/scene/吹き出しの文字数を出力スキーマにも指定する。速度向上は実APIで未計測。

構造化出力を受け取った直後、検査前にサーバーへscriptDraftとして保存する。失敗後の次の手動開始では保存案を修正資料として渡す。保存済み案は公開レスポンスに含めず、hasScriptDraftの有無だけ返す。自動の追加API呼び出しは行わない。以前の失敗では案を保存していないため復元できない。

INVALID_RESULT（脚本の形式・文字数）、PROVIDER_INPUT（HTTP400）、PROVIDER_FAILED（サービスエラー）を分ける。サービスの任意の本文は記録せず、HTTP状態と許可した固定コード・パラメーター名だけを内部保存する。型チェック・既存109件のテストが通過し、安全なエラー記録の追加テストも通過。仮APIで検査失敗→案の保存→手動修正→画像4枚の完成を確認した。有料API・実際の待ち時間は未検証。

### 画像1.5版と人物配置の調整

新規の漫画はrevision 4として別保存し、脚本GPT-5.4・画像gpt-image-1.5（medium）を使用する。revision 3のMini版は比較ボタンから再表示でき、画像や試行回数を上書きしない。人物参照は現在の場面に登場する人物の外見だけに使い、最初のコマの人物全員を後続の場面へ引き継がない。画像指示では話者を対応する吹き出しの直下に明瞭に配置することを構図より優先する。実画像の配置を保証する検証ではなく、生成指示の改善である。

検証：仮APIによる関連29テスト、TypeScript型チェックに合格。実APIは呼び出していない。画質・人物配置は次回の手動生成で確認する。

### 1ページをまとめて生成する方式（revision 5）
