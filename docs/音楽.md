# 読書中のBGM

Webの画面や保存済みBGMをすぐ確認する場合は `npm run web:quick` を使います。キー入力・QRコード表示を省略してブラウザーを開きます。新規の分析・音源検索にはキーが必要なので、`npm run web` で起動し直してください。通常のWeb起動でもQRは表示しません。起動中のファイル変更は自動反映されるため、毎回サーバーを再起動する必要はありません。

1. ターミナルで `npm start`（Webは `npm run web`）を実行します。
2. Freesound APIキー、OpenAI APIキーを順に入力します。入力は非表示で、ファイルに保存しません。WindowsはCtrl+V、VS CodeはCtrl+Shift+Vで貼り付けます。
3. 本文の画面で **BGM取得** を押します。本文の分析、環境音・音楽の検索、自動選択、共有保存、ガイド同期への反映まで自動で行います。別の編集画面は開きません。
4. **BGM ON** にした状態で **読みガイド ON** にすると、ガイドの移動と現在位置に合う音の再生が始まります。ガイドの一時停止・OFFでは音も停止し、再開すると音も再開します。BGM設定自体はONのまま待機します。**BGM OFF** にするとガイドが動いていても鳴りません。音量バーの設定は端末に保存されます。

音楽操作のボタンはこの2つだけです。曲名・作者と利用許諾は小さなリンクで表示します。取得中も本文を読み続けられ、再生中のBGMは継続します。

## 自動選曲

OpenAI（gpt-5.6-luna）で本文の状況・心情を読み取り、持続する環境音を優先します。軽量モデルで `reasoning.effort:none` を指定し、出力上限10,000トークン・既存の構造化出力を維持します。実際の雨・川・風・森・虫・町などを探し、比喩・台詞内の天候・回想を現実の環境と取り違えないよう指示します。根拠がある場面で環境音を多めにし、描写がない場面を無理に環境音で埋めません。参考：[モデル仕様](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。

Freesoundの名前・タグと検索語の一致を確認し、声や歌、単発の爆発・叫びなどは除外します。環境音に一致する録音がなければ心情に合う音楽で補います。人が曲を編集・選択する操作は不要です。音そのものをAIが聴いて評価する方式ではないため、適合には限界があります。

読みガイドが示す文字位置で場面を判定し、約2秒のクロスフェードで音を重ねます。未来の場面の曲は先取りしません。次の音の読み込み中は現在の音を保ち、ローカルの小さなパッド音を背景に常時重ねます。ガイドを一時停止・OFFにするとBGMも停止し、ガイド再開で再生を再開します。BGM OFF・音量0・別画面への移動・アプリのバックグラウンド移行では停止します。

## 保存とAPI使用量

本を開くだけでは有料分析やFreesound検索を行いません。保存済みJSONの読み込みだけを行います。ガイドが進むたびにOpenAIを呼ぶこともありません。

モデル変更は新規分析から適用します。保存済みの分析や選択曲をモデル変更だけで無効にせず、共有JSONと復旧用の応答を再利用します。

`data/music-plans/<本文SHA-256>.json` に分析・音の種類・候補・選択曲・使用トークン数を自動保存します。本文全体やAPIキーは保存しません。同じ本文・選曲方針なら、BGM取得を押し直しても保存済みの結果を使います。途中で音源取得に失敗しても、BGM取得を押すと保存済み分析から再開します。

環境音と効果音を重ねる形式はバージョン3です。旧形式は再生用に読み込めますが、BGM取得を押したときに一度だけ新方針で分析を行います。以後は新しい保存結果を再利用します。

背景は最大32場面、追加音は最大48箇所です。約250文字ごとの本文と実在する引用を使ってタイミングを決めます。扉・ノック・着水などは一度だけ、雨・風・川などは指定区間を繰り返し再生します。持続する追加環境音を2つ、単発の効果音を2つまで背景に重ねます。比喩・否定・想像を音の根拠にしないよう指示しますが、AIによる解釈と録音のメタデータによる選択には限界があります。

異なる検索は最大40種類とし、同じ効果音は複数箇所で再利用します。効果音は0.15〜12秒の録音を検索し、一致する音がなければその効果だけ省略します。背景音は継続します。ガイドの大きな移動では通過した効果音を一斉再生せず、読み戻すと再び該当箇所で鳴ります。単発音の再生中は背景を控えめにします。

**共同開発者にも再分析させないため、生成されたJSONもGitで共有してください。** 各自のPCだけにJSONがある場合や本文が変わった場合には、新たな分析が必要です。MP3自体はJSONに含めず、公開プレビューを再生時に読み込みます。

分析の本文上限は60,000文字、出力上限10,000トークンです。細かな効果音の記述を増やしたため、旧形式より出力トークンが増える可能性があります。サーバーの1回の起動につき新規分析は最大10回、同時1件までです。失敗も回数に含みます。これらは料金上限ではありません。本文を黙って切り捨てたり、分析を自動で繰り返したりしません。

分析応答は検証前にGit対象外の `.local/music-analysis` にも保存します。場面境界や検索語の表記ゆれを補正し、共有保存に失敗しても応答を再利用します。

## 動作環境

WebとiOS（Expo Go）で共通の操作です。Expo Goは開発PCのExpoサーバーに接続します。TestFlightなどへの配布にはAPIのHTTPS公開先と永続保存先の設定が別途必要です。公開時は認証とサーバー全体の利用制限を追加してください。

CC0・CC BYの音源を使い、作者・音源ページ・ライセンスを表示します。端末の音声制限やOSの割り込みによる停止までは保証しません。

API形式：[OpenAI公式 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
